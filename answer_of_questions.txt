Q1. What is the difference between a List<int> and a List<dynamic> in Dart? Why is it usually better to use a typed list like List<int>?

Answer. The difference is that List<int>  is used to store only integers while List<dynamic> can store any data types such as integers , boolean  , strings or objects. List<int> is better than that of dynamic list because it makes the code easier to understand and maintain since other programmers can clearly see what type of data the list is supported to contain. The other reason is that it provides type safety , meaning the compiler can detect errors if a wrong data type is added to the list.

Q2. In your findMax() function, why is it important to initialize your 'running maximum' variable to the first element of the list rather than to 0 or to a very small number? What could go wrong with the other approaches?

Answer. Initializing the first element of the list ensures that the comparison starts with an actual value from the list. If it were initialized to 0, the function could produce incorrect results when the list contains only negative numbers because 0 would incorrectly appear as the maximum value. Using a very small number may also causes errors if the list contains numbers smaller than that value. Therefore, starting with the first element guarantees accurate comparisons.

Q4. Describe in plain English what the for-in loop syntax does in Dart. How is it different from a traditional for loop with an index? When would you prefer one over the other?

Answer.  The for-in loop in Dart is used to iterate through each element in a collection such as a list. It automatically retrieves each item one by one without needing an index variable. A traditional for loop uses an index to access elements by their position in the list. The for-in loop is usually preferred when you only need to access the values of the elements, while a traditional for loop is useful when you need the index position or need to modify elements based on their position.

Q6. What is the difference between a synchronous function and an asynchronous function in Dart? In your Calculator class, why is divide() synchronous while computeAsync() is asynchronous?

Answer. A synchronous function runs line by line and must finish before the next instruction starts. An asynchronous function allows other operations to continue while waiting for a task. In this Calculator class, divide() is synchronous because it performs a simple mathematical calculation that finishes immediately. computeAsync() is asynchronous because it simulates a delayed operation using Future.delayed(), representing a real-world situation like fetching data from a server.

Q7. Explain the purpose of the await keyword in Dart. What happens if you forget to use await when calling an async function that returns a Future? What does your program print instead of the result? 

Answer. The await keyword pauses execution until a Future finishes and returns its result. It allows asynchronous code to behave like synchronous code. If await is forgotten when calling an async function, the program will print a Future object instead of the actual result, such as: Instance of 'Future<double>'

Q9. Why is it good design to have divide() throw an ArgumentError rather than simply 
returning 0 or printing an error inside the divide() method itself? What principle of 
function design does this reflect? 

Answer. Throwing an ArgumentError allows the function to signal that invalid input was provided. This is better than returning 0 or printing an error because the calling function can decide how to handle the problem. This reflects the principle of separation of concerns and proper error handling in function design.
